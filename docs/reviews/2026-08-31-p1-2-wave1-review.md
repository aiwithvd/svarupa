## The finding that changes how this component is tested

Earlier reviews looked for *missing* facts. This one looked for **wrong** ones, and found five constructions where the resolver emitted a `RESOLVED` edge pointing at the wrong definition.

For a product whose whole claim is that every element points at real code, a wrong edge is worse than no edge. `UNRESOLVED` is always an acceptable fallback; wrong never is.

**All 33 tests passed while every one of these was live.** The reason is structural: every fixture used a repo with exactly one plausible target, so first-match-wins, bare-name indexing, and length-sorted roots were indistinguishable from correct resolution. That is R2-1 in resolver clothing.

**One finding contested.** Fable counted 276 "duplicate edges" on flask. Verified: they are **not** duplicates. Recorded instead as a P1-3 merge contract (union evidence, never drop), with a test asserting both line numbers survive.

## Test quality

**The suite's central gap:** no test could catch a wrong-but-plausible resolution. Fixed by a decoy-fixture family where every name exists at least twice and each assertion names the specific expected `dst`.

Also noted and addressed:

- `test_candidate_edges_carry_call_site_and_definition_site` was not vacuous, but enshrined *semantically impossible* candidates (a bare call matched to instance methods). Fixing F4 would have made it vacuous for real.
- `test_hopeless_ambiguity...` asserts absence only, and passes on a graph with no resolution at all.
- `test_roots_do_not_reach_across_unrelated_trees` used a decoy with a *different* package name, so the collision it exists to guard never fired. The replacement uses the same name and goes red on the parent commit.

## Riskiest remaining untested assumption

Carried into wave 2: **that TypeScript resolution is correct, not merely present.** The Python resolver looked right for four commits while producing wrong edges. TS has three known resolver traps from Spike 0c (ESM `.js` specifiers naming `.ts` files, tsconfig `references`/`extends`, and regex-based JSONC parsing corrupting `paths`), and the decoy-fixture discipline must apply from the first commit rather than be retrofitted after a review.
