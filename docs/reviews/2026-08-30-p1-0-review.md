## The core criticism, accepted

> The riskiest assumption is that **`Lockfile.parse` will only ever be fed bytes that `Lockfile.render` produced.** That is guaranteed false, because the entire product thesis is that this file lives in git, gets merged by humans, and is diffed by CI on every PR.

Every confirmed corruption path flowed from that single unstated assumption. I had written a serializer and called it a format.

The parser did not implement its own published grammar. `docs/lockfile-grammar.md` declared `kind := [a-z_]+`; `Record.parse` never checked it, never validated field counts, and split records on line boundaries the grammar never defined.

## F10: what it means, since it cannot be fixed

`dataclasses.replace` correctly re-raises, and `copy` is safe. But `object.__new__` plus `__setattr__` builds an evidence-free `Node` that survives pickling un-revalidated, and a subclass overriding `__post_init__` bypasses everything.

Python cannot prevent this, and contorting for it would be worse than the disease.

**Consequence, recorded as binding on P1-3:** the design's claim that *"`build.py` rejects any node or edge with empty evidence"* must be an **independent second check at graph insertion**, not a comment asserting the model already did it. Constructor validation is a convenience, not the enforcement point.

---

## F13(c): the cross-platform CI job oversells itself

Accepted. The `cross-platform-bytes` job renders a hardcoded in-memory corpus, so it is pure `str` manipulation on two operating systems and can essentially never fail. It verifies the **serializer's** determinism, not the **product's**.

That is acceptable scaffolding while `detect` does not exist, but the comment calling it "Gate 2 from Spike 0" claims more than it delivers. **P1-1 must swap in a real fixture-repo build**, which is where NFD paths, dirent ordering, and case-insensitive volumes actually enter. Today's green matrix says nothing about any of them.

## Riskiest remaining untested assumption

Restated for P1-1, and it is now the second half of the same problem:

> The determinism CI currently proves that **sorting strings is deterministic**, not that **building a lockfile from a filesystem** is. The first real `detect` is where NFD paths, dirent ordering, and case-insensitive volumes actually enter.

This is the P1-1 gate.
