Svarupa now grades a codebase's health, explains every finding in plain
words, gates pull requests on the problems they add, and teaches your AI
coding tools the rules, in Python, TypeScript/JavaScript, Go and Java.

## New

- **Language packs for Go and Java**, next to Python and TypeScript/JavaScript
  (JSX in `.js` files is now parsed). Pack quality is scored on a benchmark
  of pinned public repositories.
- **Health grades** (SQALE, ISO/IEC 25010) for maintainability, security,
  reliability and performance, from 30 checks with published limits:
  complex, long and deeply nested functions, large files and classes,
  duplicated blocks, import cycles, hub modules, and design-style rules.
- **Design styles**: `svarupa design <repo>` proposes each app unit's style
  (layered, hexagonal, clean, feature-sliced and more) and writes
  `.svarupa/design.yaml` when you accept it; breaking the style is a finding.
- **Security checks**: committed secrets (the value is never stored or
  shown), SQL, shell and code injection, TLS verification off, unsafe
  deserialization, weak hashes, debug mode, CORS for every origin, and write
  endpoints without auth.
- **Performance and reliability checks**: queries in loops, blocking calls
  in async code, a datastore shared by services, hubs on every request path,
  outbound calls without a timeout, swallowed errors, and retries turned off.
- **Plain explanations**: every check says what it means, why it matters and
  how to fix it, with a before/after example in your language.
  `svarupa explain <check>` prints it; REPORT.md and the viewer show it.
  Every box on the map gets one plain sentence with its health.
- **`svarupa check <repo> --base main`** lists only the violations a change
  adds (moved or renamed code is not new) and exits 3 when it should not
  ship. `--format github` annotates pull request lines; `--format gitlab`
  writes a Code Quality report.
- **CI health gate**: `svarupa setup ci_github` and `svarupa setup ci_gitlab`
  now add a step that fails a pull request only for health problems it adds.
- **AI coding tools**: `svarupa setup ide` writes the Svarupa workflow and
  your repository's rules into Claude Code, Cursor, GitHub Copilot, Windsurf
  and AGENTS.md, and adds the MCP server where the tool has a project config.
  It only edits text between `<!-- svarupa:begin -->` and
  `<!-- svarupa:end -->`.
- **For agents**: `get_design_rules` (query and MCP) now also returns every
  health rule with its fix, and `get_health` returns the explanations.

## Upgrading

1. `uv tool upgrade svarupa`, then run `svarupa .` again: graph.json,
   REPORT.md and the viewer gain health, explanations and box sentences.
   The committed architecture lockfile is unchanged.
2. To get the health gate in CI, re-run `svarupa setup ci_github --update`
   (or `ci_gitlab --update`) and commit the updated workflow.
3. Optional: `svarupa design .` to accept a design style, and
   `svarupa setup ide` to teach your AI coding tools the rules.

Versions now follow the calendar (`YYYY.M.N`).
